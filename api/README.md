# API and website

One Node process serves the public JSON API and the server-rendered site. It reads one or more Clean builds from [`tools/wds_build.py`](../tools/wds_build.py) and [`tools/wds_census.py`](../tools/wds_census.py), plus their combined Normalized build from [`tools/wds_normalize.py`](../tools/wds_normalize.py) (see [BUILD.md](../BUILD.md) and [SCHEMA.md](../SCHEMA.md)). It reads Parquet through DuckDB. No database service.

- From Normalized, loaded into memory at startup: `table` (search and browse), `place`, `member_place`, `unit_family`, `period`, and the code sets `frequency`, `subject`, `survey`, `uom`, `scalar`, `status`, `symbol`, `security_level`.
- From Normalized, read per request: `series/<PID>.parquet` for PID lookups and the matching PID parts for cross-table series searches. Series rows are not loaded.
- From each Clean input, loaded at startup: the catalogue tables that Normalized does not copy (dimensions, members, notes, corrections, symbols, cube metadata). Exact duplicates are dropped; raw geography attributes are not loaded.
- From the Clean input that owns each PID, read per request: `obs/<PID>.parquet`.

The only client-side JavaScript is the chart (Highcharts from a pinned CDN URL); every other page works without JavaScript. A second entry point, `src/mcp.ts`, exposes the same data to AI agents over MCP (see below).

```bash
cd api && npm install
STATCAN_BUILD=/run/media/hemanth/Kingston/statcan-derived/wds-full-1 \
STATCAN_NORMALIZED=/run/media/hemanth/Kingston/statcan-derived/wds-full-1/normalized/n8 \
STATCAN_CAPTURE=/run/media/hemanth/Kingston/statcan-wds/baseline \
STATCAN_CODESETS=/run/media/hemanth/Kingston/statcan-ref/codesets/20260930T182041Z/codeSets.json \
STATCAN_UUID=72D0-2131 PORT=3000 npm start
npm run check   # tsc --noEmit
```

- `STATCAN_BUILD` (required): first Clean build directory. The Normalized manifest's `cleans[]` supplies any other Clean input paths; no extra environment variable is needed.
- `STATCAN_NORMALIZED` (required): a `normalized/<id>/` directory. The server validates every Clean build ID, family, queryable count, and manifest SHA-256 against its input record.
- `STATCAN_CODESETS` (required): captured WDS `getCodeSets` response (`codeSets.json`) with its sibling `.sha256`. The SHA-256 must match the Normalized manifest.
- `STATCAN_CAPTURE` (optional): enables original ZIP downloads only when the table's Clean report names a ZIP in this capture directory. The 2021 Census ZIPs are original Statistics Canada CSV downloads captured in the same `baseline` directory; they are not WDS observation-format ZIPs.
- `STATCAN_UUID` (optional): refuse to start unless the builds, code sets, and capture are on this filesystem, same rule as the downloader.
- `HOST` defaults to `127.0.0.1`; `PORT` to `3000` (HTTP server only).
- `PUBLIC_ORIGIN` defaults to `https://statcan2.ca`. It sets absolute Open Graph, canonical, Cite, chart/share links, OpenAPI servers, and MCP text; request-relative navigation stays relative. For local link testing set `PUBLIC_ORIGIN=http://127.0.0.1:3000`. Image footers always say `statcan2.ca`, even with an override.

DuckDB runs with 4 threads and a 2 GB memory limit. It spills to `<STATCAN_BUILD>/tmp`. Stop the server with SIGTERM or SIGINT so DuckDB deletes its spill files.

Node 26 runs the TypeScript directly; no build step. Dependencies include `hono`, `@hono/node-server`, `@duckdb/node-api`, `@modelcontextprotocol/sdk`, `zod`, `@resvg/resvg-js`, and the locally bundled Geist font files. OG cards render SVG to PNG in-process; no browser or screenshot service is needed.

## Data endpoints (`/api/v1`)

One API lives under `/api/v1`: the data endpoints below and the chart endpoints after them. One OpenAPI document at `/api/v1/openapi.json` covers both.

| Path | Result |
|---|---|
| `GET /build` | Combined Clean build ID, capture, inventory SHA-256, code-set ID and SHA-256 (`code_sets`), queryable and failed PIDs; `normalized.cleans[]` identifies each input build, directory, family and manifest SHA-256 |
| `GET /coverage` | Inventory count, captured count, built and queryable counts, the same per `family` (`wds`, `census_2021`), failed tables and Normalized warnings |
| `GET /tables?q=&archived=&kind=&family=&queryable=&limit=&offset=` | Search over all 8,271 Normalized `table` records. Every term must equal the PID or CANSIM ID or appear in `search_text` (title, dimension names, member names, notes). Results carry `kind`, `family`, `frequency_en`, `subject_en`, `period_min`, `period_max`, `series_count`, `unit_families`, `place_levels`, and `title_hits`, `dimension_hits`, `member_hits`, `note_hits`, `text_hits`. Ranked by title hits, then queryable first. |
| `GET /tables/{pid}` | `cube` (the Normalized table record without `search_text`), metadata blocks (dimensions with members; dimension 1 members carry `place_id` and `place_match`), notes, corrections, symbols, survey, subject, official names for the inventory's code lists (`subject_labels`, `survey_labels`), build report, links |
| `GET /tables/{pid}/observations?from=&to=&vector=&m1..m9=&limit=&offset=` | Filtered, paginated rows with member labels, `status_en`, `symbol_en`, and from Normalized: `period_start`, `period_end`, `period_kind`, `place_id` (dimension 1), `unit_family`. Max 1,000 rows per page. `409` with the build errors if the table failed the build, `404` if not built. |
| `GET /tables/{pid}/series?from=&to=&vector=&m1..m9=` | One series per coordinate (equal to the vector in WDS tables; Census tables have no vector) for the same filters: `vector`, `coordinate`, `name`, `labels`, `unit`, `scale`, `period_kind`, `points: [[ref_date, value_num, status, period_start, period_end], …]`. At most 50 series and 200,000 points; `413` above that. |
| `GET /tables/{pid}/observations.parquet` | The build's Parquet file, `X-Content-SHA256` header |
| `GET /tables/{pid}/source.zip` | The unchanged Statistics Canada ZIP, `X-Content-SHA256` from the capture manifest |
| `GET /series?q=&pid=&place_id=&unit_family=&limit=&offset=` | Series search over Normalized `series`. Query normalization handles a small semantic vocabulary (`quality of life`/`well-being` -> `life satisfaction`, `inflation`/`cost of living` -> CPI all-items). Bare CPI queries add `all-items` unless the query names a component such as food, shelter, energy, goods, or services. Every normalized word must appear in the table title or a member label; a term like `v41690915` must equal the vector. `pid`, `place_id`, `unit_family` are exact. On a combined build such as `n8`, unfiltered broad searches with over 1 million candidate series use title-matching tables first and scan at most 12 table parts / 5,000 series rows (if none fit, the first 5,000 rows of the best title-matching table). `total` then counts only that scan, not all matches; `X-Statcan-Search-Scope: capped` marks this case. Supply `pid` for exhaustive counts; scoped and single-Clean searches remain uncapped. Each result: `pid`, `vector`, `coordinate`, `title_en`, `kind`, `labels`, `place_id`, `place_name`, `uom_code`, `uom_en`, `unit_family`, `scalar_code`, `scalar_en`, `decimals`, `period_kind`, `period_min`, `period_max`, `n_obs`, `n_published`, `terminated`, `last_status`, `phrase_hit`, `title_hits`, `links`. Ranked by exact table-title phrase for CPI, then any title hit, then current before terminated, then table and member order. |
| `GET /series/{pid}/{vector}` | One series: its Normalized row, `labels` (dimension, member ID, member name), `place`, unit (`uom_en`, `unit_family`, `unit_symbol`, `unit_base_year`, `unit_note`), `scalar_en`, a `citation`, and every point with `ref_date`, `period_start`, `period_end`, `period_kind`, `value`, `value_num`, `status`, `status_en`, `symbol`, `symbol_en` |
| `GET /series/{pid}/c/{coordinate}` | The same, by coordinate. This is the key for Census tables, which have no vector; it also works for WDS tables. `409` when the Normalized row does not match the observations for that coordinate. |
| `GET /places?q=&limit=&offset=` | Places whose name holds every term, or whose `place_id`, DGUID, or `geo_code` equals one. Countries first, then provinces and territories, then other schemas. Each row adds `n_tables`. |
| `GET /places/{place_id}` | The place, its `parent`, its `vintages` (every `place` row with the same `schema` and `geo_code`, for example Ontario `2011A000235`, `2016A000235`, `2021A000235`, `code:0002:35`), and `subjects`: every table that maps a geography member to any vintage, grouped by the table's first subject. Each table lists its matching `members` (`member_id`, `member_name`, `place_id`, `vintage`, `match`), `n_series`, a `citation`, and `series_search` links. |

Every response carries the headers `X-Statcan-Build` and `X-Statcan-Normalized-Build`. Every JSON body carries `build_id`, `normalized_build_id`, `capture_id`, `language`. Observation and series responses add `source_sha256` and `parquet_sha256`. A developer who pins both build IDs and re-runs the same query against the same directories gets the same rows.

Values stay as published: `value`, `status`, `symbol`, `ref_date`, `uom`, `scalar_factor` are the raw strings; `value_num` is derived and null when nothing was published. A blank value is not zero. Member labels come from the official member table, not from the observation file.

## Chart endpoints (`/api/v1`)

`POST /api/v1/view` takes a `ViewSpec`. `GET /api/v1/view?s=<base64url JSON>` runs the same spec.
The response is a `ViewResult`: resolved member IDs, series, axes, notes, source citations, warnings, and share/export links.
Every JSON response includes `build_id` and `normalized_build_id`; errors have `error` and provenance (400 invalid input, 404 unknown PID, 422 invalid view).
Published API descriptions: `https://statcan2.ca/api/v1/openapi.json` and `https://statcan2.ca/api/v1/openapi.json`. Resolved view and citation links use `PUBLIC_ORIGIN`, not a proxy or request Host header.

| Path | Result |
|---|---|
| `GET /cubes?q=&limit=` | Queryable tables with PID, table number, title, frequency, period bounds, family, and unit families. Limit 1–100. |
| `GET /cubes/{pid}` | `CubeInfo`: dimensions, members, roles, defaults, units, periods, and official URL. Defaults select a jointly published coordinate from the latest period (last 12 months for monthly tables), favoring the sole total root, then other roots, then remaining members. If no recent numeric observation exists, the original member-order defaults apply. Cube metadata is cached for the process's immutable build. |
| `GET /cubes/{pid}/views` | Labeled starter specs. Census snapshots default to bars across up to 20 categories (provinces and territories where available), rather than a one-point line. |
| `GET /highlights` | Twelve build-pinned home cards from `data/ref/highlights.csv`: latest published value, change, five-year sparkline, source table, and exact chart spec. Cached in memory per build. |
| `GET /plan?q=&view=1` | `PlanResult`: `ok`, `need_more`, or `no_match`; spec and alternatives when available. `view=1` includes the chart. |
| `GET or POST /view` | Resolved `ViewResult` from URL parameter `s` or JSON `ViewSpec`. |
| `GET or POST /view.parquet`, `/view.csv` | One row per displayed point, hidden series included. GET takes `s`; POST takes the same JSON spec. |

`ViewResult.series[].points` remains `[ref_date, period_start, value|null, status]`. Missing period rows are explicit nulls with a blank status; source marks such as `x` are retained, not turned into invented `..` marks. `coverage.first`/`last` bound published ref_dates; `gaps[]` lists only internal null runs between those bounds, split by mark with its official meaning or “Not published.” `unpublished` retains entirely missing requested series. `gap_parts.unpublished` names up to three missing combinations, then summarizes four or more; `gap_parts.time` explains internal gaps. Either is null when absent. `gap_note` joins the non-null parts with a space, or is null. Clients can omit the unpublished part when a `substituted_geography` warning already explains it. A nearby published geography can accompany, not replace, a requested unpublished series; `substituted_geography` identifies that alternative.

On the combined `n8` build, `/plan` uses one Census snapshot date. It resolves named 2021 places from the Normalized gazetteer, including city-first queries and individual components of hyphenated CMA/CA names (for example, Ottawa in Ottawa–Gatineau and Cambridge in Kitchener–Cambridge–Waterloo). Place-name words are excluded from topic and table matching; for a single-place snapshot the concept chooser also sees the original request and resolved place, so a local age breakdown remains a Census age question. A lexical WDS alternative replaces a Census concept only when its table covers the requested geography and either matches the topic or is a stronger match for a requested time range. Language and speaker questions without a better topic match use the appropriate Census language table. A single place fixes geography while a small topic category such as age, language, tenure, or income group becomes the bar x axis. Explicit census subdivision requests use subdivisions.

For Census snapshots, requests by province, province and territory, or city put geography on the x axis and topic categories in separate bar series. Comparisons of two or three named places also use geography on the x axis in query order, resolving CMA components to their full metropolitan area when that table supports them. An unresolved named comparison place produces `member_not_found` in plan steps and, with `view=1`, view warnings; any available comparison places remain plotted rather than silently dropping the warning. Explicit modes such as bike and transit select Bicycle or Public transit instead of broad commuting categories. Other Census dimensions stay at their default totals unless the query names them; a request for time leaving for work still selects its categories. Census geography candidate prompts stay below 255 entries; table-number requests also return category bars rather than one-point charts. When an annual WDS series covers the same concept and the question asks for a trend, `/plan` prefers that series over a Census snapshot. Everyday travel-to-work questions select Census main mode of commuting; car sales select current new motor vehicle sales (monthly 20100085 or annual 20100086), with passenger cars selected when asked.
If no compared Census place resolves, the Census view falls back to Canada and warns for each missing place. For Census and WDS comparisons, the planner first prefers a table covering every named place; if none does, a table covering a real place can keep the requested topic while warning about each missing place. CMA components also match hyphenated WDS geography labels, including Kitchener–Cambridge–Waterloo rental tables.
Province or territory names select province/territory members, not same-named municipalities. For example, vehicle registrations in Quebec use the published Quebec total in quarterly table `20100025`; an unpublished Québec municipality row must not trigger a fallback to monthly vehicle sales.
For a named city's category breakdown, `/plan` checks the Census subject against the request and uses a table that covers the city. `population of Saskatoon by age` selects broad age groups in `98100030`, not an income table that happens to have age as a secondary dimension.

For multi-period WDS selections, `/plan` defaults to the latest five years of published values, time on x and a line per requested province or category. Short annual histories use every available year. Explicit windows (`past 1yr`, `since 2015`, `2021–2025`, `all time`) take precedence; a window alone never changes levels into percent changes. Inflation, growth, or `% change over 1 year` requests use year-on-year percent change. A snapshot, `latest`, `in 2021`, `ranking`, or an explicit bar/column request uses category bars at one available period; more than 13 series also fall back to latest-period bars with a reason in the plan steps. Explicit line, area, stacked area, bar, stacked column, and horizontal bar map to the corresponding chart options. Pie and table requests use supported category bars with a `chart_fallback` warning (values remain available in the Table panel); non-additive or negative stacks likewise fall back to unstacked values.
The planner tolerates unambiguous misspellings of known places, regions and statistical concepts before table/member matching. It parses time windows from the original request, then removes those phrases for matching, so `population growth, praries vs. atlantic, past 10 years` keeps the requested window and group membership. `yoy`, `y/y`, `year over year`, `annual change` and `12-month change` request `pct_change_yoy`.
An explicit `by <category>` request selects the dimension's published child categories, or its top-level members when the dimension is flat, rather than trusting a single Jev-chosen member; singular and plural names match. When that would create more than 13 lines, the planner shows latest-period category bars instead. `deaths by cause in Ontario` displays the published grouped causes from `13100932`, not one selected cause.
`causes of death in Ontario` uses the same grouped-cause selection as `deaths by cause in Ontario`; cause level is unchanged. Named region comparisons put the group labels in the generated title, without changing `View` title construction. The ten home-page demos have forty input variations in `test/plan_eval.ts`; run them with `node --env-file=.env test/plan_eval.ts --split=demo-variants`.
For multi-layer charts, `/plan` keeps published levels when the query does not request a transform and the units match. Distinct level units across named concepts (for example, dollars versus CPI) default to `index_first`, first published point = 100, so both lines share one axis; rates and percentages keep two axes alongside a level or index. An explicit transform always wins. `indexed to 2015`, `index 2015 = 100`, `rebased to Jan 2020`, and `relative to 2019` with index meaning request `index_first` and the stated `index_base`, independently of the visible time window. Bare `indexed` or `indexed to 100` uses the first published point in the window; more than two published unit axes also trigger first-point indexing to avoid dropping a series. When provinces and territories come from tables with different methods, the chart labels that distinction using short method names and table numbers.
`ViewSpec.index_base` applies to `index_first` and accepts `YYYY`, `YYYY-MM`, `YYYY-Qn`, or `YYYY-MM-DD`. Each series uses its first published point in that base period as 100, even when it falls outside the displayed window; without a base it uses the first published point in the window. A missing or zero base yields null index values and `index_base_missing` for that series. `ViewResult.index_note` explains the calculation without presenting it as a published table note. The unit, generated title, source citation, and encoded URL name the base.

For an `A vs B` request that needs separate tables, `/plan` chooses each table and its members for its own subject, limits layers to the named concepts, and prefers a matching frequency among otherwise good candidates. `spec.layers`, the generated title, and the series follow the subjects in typed order. An unavailable default aggregate may be replaced by its published counterpart rather than leaving that layer blank.

Residential-property sales use the number of properties sold, not housing starts, property-owner counts, or sale prices. Table `46100057` publishes 2018 sales for Nova Scotia, New Brunswick, and British Columbia; a by-province chart contains only those three published provinces.

CPI table `18100004` lists Calgary, Halifax, and Saskatoon as geographies but publishes no Food observations for those cities. A member's presence does not guarantee the requested intersection. When some requested combinations are published, `/plan` keeps every requested member and the view marks the unpublished series. When none are published, it keeps those series, adds the nearest published geography for the same CPI component (for example, Alberta Food for Calgary Food), and returns a short `reason` and `substituted_geography` warning. It never presents city All-items as city Food.
For a `by province` or `provinces and territories` chart, a table with no published territory totals may instead include one city per territory: its capital, or its sole city. The geography selection includes those city members alongside provincial totals and emits `territory_proxy`, stating that the cities are not territory aggregates; `provinces only` excludes them. An explicit territory request such as `CPI in Yukon` selects Whitehorse with the same warning. Proxies never participate in sum or ratio groups. A missing city/component observation stays null and retains its `no_data` warning rather than inventing a territory value.

For commuting, the Census planner uses Jev's member choice for inflected and synonymous travel methods, then selects the published reporting category: Walked and Bicycle stay specific; bus and rail submodes use Public transit, and driver submodes use Car, truck or van. A request for the overall mode breakdown still shows multiple categories.

Example:

```json
{"v":1,"layers":[{"pid":"18100006","dims":{"2":{"use":"series","members":{"in":["All-items","Food"]}}}}],"time":{"preset":"1Y"},"transform":"pct_change_yoy","chart":{"type":"line"}}
```

Dimensions not in `dims` use their default member. `fixed` requires one member. `series` makes separate lines. `x` makes bar categories. `sum` adds only compatible additive values; a missing component gives a null point. Member sets accept `eq`, `in`, `contains`, `role`, `region`, `childrenOf`, `descendantsOf`, `all`, `any`, `and`, and `not`. Presets (`latest`, `1Y`, `2Y`, `5Y`, `10Y`, `20Y`, `max`) count from selected data. `from`/`to` override presets. The supported transforms are `level`, `pct_change_yoy`, `pct_change_period`, `pct_change_window`, `index_first`, and `share_of_x`. With `index_first`, optional `index_base` accepts `YYYY`, `YYYY-MM`, `YYYY-Qn`, or `YYYY-MM-DD`: the first published point inside that period equals 100, even if the point lies before the visible window. Without it, the first published point in the window equals 100. Charts are `line`, `area`, `bar`, `stacked_bar`, `stacked_bar_100`, or `stacked_area`.
For `pct_change_yoy` and `pct_change_period`, the API calculates with earlier published periods before trimming to the requested window. Monthly YoY looks back 12 months, quarterly 4 quarters, annual 1 year; period change looks back one period of that layer. A request from August 2023 through August 2026 yields 37 monthly points, including August 2023 when August 2022 exists. If earlier source data is unavailable, those requested points stay null; the time-axis start and subtitle period use the first non-null point. Warmup periods never appear in the chart's points, Table panel, CSV, or Parquet.
Region ids and their PT codes, aliases, source, and limitations are available at `GET /api/v1/regions` and in `data/ref/regions.csv`. `{ "region": "prairies" }` resolves only DGUID-linked province/territory members, never the historical code-only Northwest Territories including Nunavut. A named `groups` entry has `label`, `members`, optional `region`, and optional `agg` (`auto`, `published`, `sum`, `ratio`); omitted `agg` means `auto`. Use `members: { "not": { "all": true } }` on the dimension to display groups without also showing ungrouped members. `auto` uses an exact published aggregate first, otherwise a compatible additive sum, otherwise a curated ratio from `data/ref/ratio_rules.csv`. Explicit `published` without an exact aggregate emits `group_published_unavailable` and follows that same `auto` fallback, including `group_not_combined` if no safe combination exists. Census `View` counts may sum; percentages, rates, and price indexes never receive an unweighted average. If no safe combined value exists, member lines remain separate with the same `group` tag and a `group_not_combined` warning. Missing PT codes produce `group_partial`/`group_missing`; partial groups are not silently summed.
Grouped series expose `group_method`, `group_members`, and `group_of` for a published aggregate. Grouped x-category bars expose `category_groups` and `category_methods` aligned with `categories`, including non-combined members. `group_notes` lists the method, members, and ratio formula or fallback for the Notes panel; source citations append that provenance. CSV and Parquet include `group`, `group_method`, and `group_members` columns, and Parquet also carries `statcan.group_notes` metadata. Physiographic regions have no provincial membership; the planner may return `no_match` with `reason`.
`/api/v1/plan` interprets named regional comparisons such as `population prairies vs atlantic vs central`, `Ontario vs the Maritimes population`, and `unemployment rate, provinces vs. territories`. `by region` requests Atlantic, Quebec, Ontario, Prairies, BC, and Territories where published. The planner prefers a table covering each whole group, then adds a same-subject table for a missing group rather than dropping it; for unemployment, provinces use `14100287` and Territories use the three-month moving-average table `14100292`. The `group_method` plan step names that methodological difference, and grouped series retain their source and aggregation provenance. CPI groups retain tagged provincial lines instead of averaging price indexes. A physiographic request such as `Canadian Shield population` returns `no_match` with a reason rather than mapping the Shield to provinces.
When a group comes from a table with a different statistical method, annotate that source layer with `method_difference: "<message>"` (1–500 characters). The resolved spec retains the message; the view emits one `group_method_difference` warning for that layer and copies the message into each displayed `group_notes[]` entry sourced from it. For example, annotate `14100292` when comparing its three-month moving averages with monthly `14100287` estimates.
The planner sets `method_difference` on the territories layer when it compares its three-month moving-average labour-force estimates with monthly provincial estimates; the view warning and Notes then carry that message.
Series names use selected `series` members or group labels. Without those, they use fixed measure members, then the table title. In a multi-layer view with different short subjects, each series starts with its layer's subject unless its own label already names it. With the same short subject, series names keep only the member or group label. A table number breaks any remaining name collision. Single-layer names stay unchanged. The historical "Northwest Territories including Nunavut" member has role `region`, not `territory`, so `{ "role": "territory" }` sums only the current three territories.
Without `spec.title`, a chart title starts with fixed non-default non-geography members (measure first), or the table title before its first comma outside parentheses. Two or three explicitly named series in one non-geography dimension lead with their labels joined by `vs`; geography series keep the fixed/table lead. Role-selected series and four or more series keep that lead. An x chart with two or three explicitly named categories adds their names with `vs` (`Ontario vs Quebec`); otherwise it uses the selected members' scope: `by province`, `by territory`, `by province or territory`, or `by <dimension>`. NAICS and ICD-10 category axes use the shorter `by industry` and `by cause of death` in generated titles. A deaths measure omits the mortality-rate qualifier; average weekly earnings omits its overtime and employee qualifier. The full classification labels remain on `ViewResult.x.dimension` with their source capitalization. A scope already at the end of the title is not repeated. Trade views with selected country-of-origin/export partners lead with the trade concept instead of repeating partner qualifiers (`Imports from the United States` when both select the United States). Multiple layers with different short subjects join those subjects with `vs`; layers with the same subject show it once, followed by their distinct group or member labels when there are at most three (for example, `Unemployment rate, Provinces vs Territories`). A window-change title uses the selected duration (`over 1 year`, `over 2 years`, etc.) or `since <year>` for explicit dates.
For named geography series, a city drops its trailing province only when that province is also compared: `Food: Calgary vs Alberta`. Series labels retain the full published names. Other geography comparisons keep their existing names and punctuation.
When the first comma-delimited clause is an organization or source name, such as `Canada Mortgage and Housing Corporation`, `Bank of Canada`, or a survey name, the view title instead starts with the next topic clause. It omits trailing scope introduced by `for`, `by`, or `in` (`Average rents` rather than the publisher or `average rents for areas …`). The official full title remains in `sources[].title` and citations.
For a single-layer chart with exactly one explicitly named `series` member, the title uses `<lead>: <member>` before the x comparison. This rule applies to WDS and Census.
The subtitle keeps fixed qualifiers not already in the title, the period, and units for level views. For category charts, `pct_change_window` and `index_first` show the full comparison period in both the subtitle and `period.from`/`period.to`; other category charts show the selected date. Preset window comparisons include the start boundary. Each full table title remains in `sources[].title`.
For a single displayed period, a Census `Statistics` or `View` qualifier beginning with that period's year omits the repeated year, regardless of the qualifier's case (`2021 Counts` or `2021 counts` becomes `Counts · 2021` or `counts · 2021`). A different year remains explicit (`2016 counts · 2021`).
Census view display titles omit the table's geography suffix after `:` and trailing `by` dimensions when each is fixed at its total or is the x axis. A selected non-Canada place appears by short name in the title and by full name in the subtitle. Named geography x comparisons also use short names in the title (`Victoria vs Ottawa – Gatineau`), while `categories`, axis tooltips, and the Table panel retain the full names. The x dimension omits its `(N)` member count; a language x axis is labeled `Language`. Default Census series labels shorten `Total - …` to `Total` and year-prefixed `Counts` to `Counts`. The stored table title, `sources[].title`, citation, and Cite panel keep the official title.
When the published unit already names the scalar (for example, `Persons in thousands`), view labels do not append it again. Published values stay unchanged. With `chart.scale_values`, the view multiplies once by the official scalar exponent and drops the embedded scale wording from the unit; the chart, Table panel, CSV, and Parquet use the same value and unit.

Census cells have no vector IDs and no published unit code. Use `/series/{pid}/c/{coordinate}`; `CubeInfo.units` is empty rather than guessing units from member labels. A broad Census view is rejected before scanning the observation file when it selects over 200,000 coordinates; an x selection is limited to 500 categories. Mixed Census/WDS views include a `mixed_family` warning.

Downloads include series keys, resolved coordinates, vectors, period bounds, plotted value, original published value when unchanged, status, unit, scale, family, transform, hidden state, and any group method/members. Explicit missing periods remain rows with null values and their actual (possibly blank) status. CSV serializes lists as JSON strings. Parquet metadata includes the resolved spec, citations (including unpublished and gap provenance), gap note, group notes, build IDs, and notes URL. DuckDB writes temporary exports to `<STATCAN_BUILD>/tmp`, then deletes them after streaming.

### Periods

Normalized `period.parquet` stores `period_start`, `period_end`, and `period_kind` per `(pid, ref_date)`. The API joins that table for observations and series points; it does not carry a copy of the period rule.

## Official labels

Labels come from the Normalized code-set files. The response never replaces a code with a label: the raw code stays and an `_en` field sits next to it.

- Frequency: `frequency_code` and `frequency_en` (a column of the Normalized `table`).
- Subject and survey: `cube.subject_codes` and `cube.survey_codes` stay; `subject_labels` and `survey_labels` list `{subject_code, subject_en}` and `{survey_code, survey_en}`. A code missing from the code set gives `null` and the page shows `code <n>`. `cube.subject_en` and `cube.survey_en` are the Normalized lists in inventory order.
- Status and symbol: observation rows carry the printed mark (`E`, `F`, `..`, `x`, `p`), not the numeric code, so `status_en` and `symbol_en` are looked up by the code set's `representation`. `x` comes from Normalized `security_level.parquet`. Blank marks have `null` labels. The site shows the label as a `title` tooltip on the cell.
- Unit and scale: series responses carry `uom_en` and `scalar_en` next to `uom_code` and `scalar_code`. Observation rows keep the unit and scale text from the file.
- `archived` has no WDS code set. The site maps 1 to "archived" and 2 to "current" from a constant in `db.ts`; the API returns the raw code only.

## Site

- `/` shows pinned indicators before a question becomes a chart. The chart's Table panel shows the selected values inline; Notes, Cite, Download, Screenshot and Share stay on the chart page.
- `/api` documents the read-only JSON API. `/mcp` lists the nine MCP tools and the public connection URL. Old `/tables/{pid}` links redirect to a chart query; old series and place pages redirect home.
- `/og/site.png`, `/og/chart.png?s=<base64url ViewSpec>`, and `/og/text.png?title=...` produce 1200×630 Geist/Geist Mono PNG social cards. The site card uses the public host, a one-line description, and a faint decorative plot. The chart card uses the scaled layout, palette, note block, and source footer from `public/export-layout.js`; value-axis labels use round intervals. Mixed-frequency lines connect across periods the series does not publish, but break at a missing period on its own cadence. Direct line labels reserve enough space for the full series name. Nominal categories turn horizontal when there are more than six categories or a label exceeds 24 characters; they show the largest 20 values that fit, then a remaining count. Ordinal buckets keep published member order and all categories: columns for up to 24, horizontal bars above 24. An unpublished selection's gap note stays above the plot. A missing or invalid chart spec uses the site card. Cards use a 200-entry build-scoped in-process LRU and `Cache-Control: public, max-age=86400`. The OpenAPI document lists these root-relative paths.
- Annual and Census chart periods display as years in the subtitle and export/OG footer, even when the stored period starts on January 1. Cite shows the source capture date as a full date, not a chart period.
- Every HTML page emits a `https://statcan2.ca` canonical link and absolute Open Graph and Twitter summary-large-image metadata (or the configured server `PUBLIC_ORIGIN`). Exact `/?s=...` chart links render their view for title, description, and image; a `q`-only page uses the query and generic site image for metadata, without planning for the image. Browser Share and API snippets use the published site origin, never the request host.

Notes are shown as escaped text, so upstream HTML links appear literally rather than being rendered. Pages are plain structure; styling will come from `DESIGN.md`.

### Charts

Time series with more than one point use a full-height Highcharts line chart. The x-axis uses `period_start`, the tooltip renders readable month/year labels, and `value_num` stays null for unpublished values. The full series stays in the plot data so range changes do not fetch or rebuild the chart. The chart mounts after page layout so it fills the available height. A snapshot or one-point series links to its reference page instead of drawing a misleading line.

The chart options are JSON in `<script type="application/json" id="chart-config">` and a small inline script mounts them. Highcharts 13.1.1 loads from jsDelivr with a Subresource Integrity hash. Its licence is free for non-commercial use, which covers this personal, non-profit project; check the [Highcharts licence](https://www.highcharts.com/license) before any commercial use. If it does not load, the page shows a one-line message; Download and API remain available.

## Normalized limits

- The `n8` Normalized build validates both WDS and Census Clean manifests and resolves observations by PID family. `test/combined.test.ts` runs when the manifest lists both `wds` and `census_2021` Clean inputs.
- Large Census geography dimensions are available through `/api/v1/cubes/{pid}` and `/api/v1/tables/{pid}`. HTML reference pages list their first 100 members rather than embedding tens of thousands of rows.
- Concurrent-load behavior is not measured.

## MCP server

Public clients connect to `https://statcan2.ca/api/mcp` using stateless Streamable HTTP. POST creates a fresh server and transport per request; GET and DELETE return 405 because there is no session or server event stream. No authentication is required, and all nine tools are read-only. `src/mcp_tools.ts` exports `createMcpServer(db)` for both transports and the `mcpTools` list rendered by `/mcp`. `src/mcp.ts` remains the stdio entrypoint for local builds; it does not call HTTP. Both use the same `Db` build. Stdio needs `STATCAN_BUILD`, `STATCAN_NORMALIZED`, `STATCAN_CODESETS` and optionally `STATCAN_CAPTURE`, `STATCAN_UUID`, `PUBLIC_ORIGIN` (not `PORT`). It writes only to stderr apart from protocol messages.

| Tool | Arguments | Result |
|---|---|---|
| `search_tables` | `q`, `archived?` (`"1"`/`"2"`), `queryable?`, `limit?` (max 100, default 25) | Matching table records with `kind`, `frequency_en`, hit counts, and a `citation` for each |
| `get_table` | `pid` | Metadata, dimensions with all member IDs (dimension 1 with `place_id`), notes, symbols, build report, `subject_labels`, `survey_labels`, `time_series` |
| `get_series` | `pid`, `from?`, `to?`, `vector?`, `m1..m9?` | Same series as `/tables/{pid}/series`, points with `period_start` and `period_end`; error above 50 series |
| `get_observations` | `pid`, `from?`, `to?`, `vector?`, `m1..m9?`, `limit?` (max 1000, default 100), `offset?` | Same rows as `/observations`, with `total` |
| `search_series` | `q`, `pid?`, `place_id?`, `unit_family?`, `limit?` (max 100, default 25) | Same results as `/series`, with a `citation` for each |
| `get_place` | `place_id` | Same as `/places/{place_id}`: place, parent, vintages, tables by subject, a `citation` for each table |
| `get_cube` | `pid` | Chartable cube with dimension roles, member roles, defaults, and units |
| `run_view` | `spec` (`ViewSpec`) | Resolved chart, compact points, notes, warnings, and source citations |
| `plan_chart` | `q` | Planner status, suggested `ViewSpec`, and alternatives |

Every result has `build_id`, `normalized_build_id`, and a `citation` such as `Statistics Canada, Table 18-10-0006-01, Consumer Price Index, monthly, seasonally adjusted, captured 2026-09-30, build wds-full-1, normalized n8`. The date is the capture date of the source ZIP. Tool descriptions say the data is not official and that a blank value is not zero. Errors come back with `isError: true` and a message.
